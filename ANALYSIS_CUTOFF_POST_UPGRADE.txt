Known pre-existing defect fixed during this session (unrelated to the
706ff19 feature upgrade itself, but blocking clean measurement of it):
  backend/utils/sqlite_runtime.py connect_rw() returned a bare sqlite3.Connection;
  `with connect_rw(...) as conn:` (37 call sites) never closed the connection
  because sqlite3.Connection.__exit__ only commits/rolls back. Under the
  cold-start burst immediately after the 706ff19 deploy (model retraining +
  historical collection + live position monitoring all firing at once), this
  leak caused DAY's update_scoreboard() to fail with "database is locked" on
  100% of bar cycles for 30+ minutes, and all 4 DAY per-coin model
  promotions failed. Fixed in commit b1d5ffa (connect_rw now returns an
  auto-closing wrapper; zero call-site changes required). A broader,
  pre-existing pattern of raw `with sqlite3.connect(...) as conn:` (same bug,
  ~21+ more call sites in portfolio_engine.py alone) was found but NOT fixed
  in this session — flagged as a known follow-up, out of scope for tonight's
  proof run since it does not block trade-level correctness (see full report).
